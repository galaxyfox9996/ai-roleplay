## 目标

把当前页面从“普通聊天网页”优化成“互动叙事游戏界面”。

核心目标：

- 主区域更适合阅读剧情。
- 行动选项更像游戏选择，而不是普通按钮。
- 左侧只保留当前游玩必要状态。
- 存档、角色卡、世界书编辑器从常驻左侧栏中拆出。
- 桌面端和移动端都有清晰可用的布局。
- 保持现有后端 API 不变，优先改 `static/index.html`、`static/styles.css`、`static/app.js`。

## 当前问题

- 左侧栏内容过多，存档、状态、角色卡、世界书、模型信息全部堆在一起。
- 剧情阅读区视觉层级偏弱，像聊天记录，不像互动叙事舞台。
- 行动选项、自由输入、角色台词之间区分不够明显。
- 编辑器常驻占用空间，干扰沉浸式阅读。
- 移动端需要更明确的单列和抽屉交互。

## 设计原则

- 剧情优先：主视觉服务于剧情阅读，不让编辑器抢占注意力。
- 状态轻量：左侧只展示“当前局”必要信息。
- 管理收纳：存档、角色卡、世界书、设置都进入抽屉或弹窗。
- 操作明确：新游戏、继续存档、删除存档、保存编辑都有明确反馈。
- 保持简单：不引入构建工具，不改变 API，不增加复杂依赖。

## 桌面端布局

推荐布局：

```text
┌──────────────────────────────────────────────┐
│ 顶部栏：世界名 / 角色名 / 存档 / 编辑 / 设置 │
├──────────────┬───────────────────────────────┤
│ 状态侧栏     │ 剧情舞台                      │
│ 当前目标     │ 场景叙述                      │
│ 地点/时间    │ 角色台词                      │
│ 氛围/物品    │ 玩家行动记录                  │
│ 模型状态     │                               │
├──────────────┴───────────────────────────────┤
│ 行动选项 1 / 行动选项 2 / 行动选项 3         │
│ 自由输入框 + 发送按钮                        │
└──────────────────────────────────────────────┘
```

实现要求：

- `.shell` 改为三块结构：顶部栏、主体、底部行动区。
- 主体内部使用两栏：状态栏 + 剧情舞台。
- 状态栏宽度建议 `280px` 左右。
- 剧情舞台内容最大宽度建议 `860px`。
- 底部行动区固定在页面底部或主布局底部。
- 存档、角色卡、世界书不要常驻显示，改成抽屉。

## 移动端布局

推荐布局：

```text
顶部：世界名 + 菜单按钮
中间：剧情舞台
底部：行动选项 + 输入框
抽屉：状态 / 存档 / 角色卡 / 世界书
```

实现要求：

- `max-width: 860px` 以下切换单列。
- 状态栏变成可折叠状态卡，默认只展示目标。
- 存档、角色卡、世界书使用全屏或底部抽屉。
- 行动选项纵向排列。
- 输入框固定在底部，避免被内容挤出屏幕。

## 组件拆分方案

### 1. 顶部栏

目标：提供全局导航，不承载大量内容。

包含：

- 当前世界名
- 当前角色名
- `新游戏`
- `存档`
- `角色卡`
- `世界书`
- `设置`

验收标准：

- 用户可以从顶部进入存档和编辑器。
- 顶部栏不超过一行。
- 移动端顶部栏保留世界名和菜单按钮。

### 2. 状态面板

目标：只展示当前游玩状态。

包含：

- 当前目标
- 章节
- 地点
- 时间
- 氛围
- 物品
- 模型状态

验收标准：

- 不再显示角色卡和世界书编辑表单。
- 当前目标视觉优先级最高。
- 物品用 chip 样式展示。
- 模型状态弱化展示，不抢剧情焦点。

### 3. 剧情舞台

目标：让剧情阅读更沉浸。

包含：

- AI 场景叙述卡片
- 角色台词区
- 用户行动卡片
- AI 来源标记

验收标准：

- AI 剧情卡片和用户行动卡片明显区分。
- 台词有 speaker 标签。
- 正文行高适合阅读，建议 `1.7` 到 `1.9`。
- 最新消息自动滚动到底部。

### 4. 行动选项

目标：更像互动叙事游戏选项。

包含：

- 三个选择按钮
- 类型标签：对话、行动、观察、离开
- 选项编号：`01`、`02`、`03`

验收标准：

- 三个选项在桌面端横排，移动端竖排。
- hover/focus 有明确反馈。
- 点击后进入 busy 状态，防止重复提交。

### 5. 自由输入

目标：支持用户不受选项限制地行动。

包含：

- 多行输入框
- 发送按钮
- 快捷键提示

验收标准：

- 支持 Ctrl/Command + Enter 发送。
- busy 时输入框和按钮禁用。
- 输入为空时不提交。

### 6. 存档抽屉

目标：从左侧栏拆出存档管理。

包含：

- 存档列表
- 当前存档高亮
- 继续存档
- 删除存档
- 新游戏入口

验收标准：

- 点击存档可以继续。
- 点击删除需要二次确认。
- 删除当前存档后自动切换到最新存档，或显示新游戏引导。
- 删除操作调用现有 `/api/session/delete`。

### 7. 角色卡抽屉

目标：收纳角色卡编辑器。

包含：

- 名称
- 身份
- 性格
- 说话风格
- 规则
- 保存按钮

验收标准：

- 打开抽屉时填充当前选择角色。
- 保存调用 `/api/editor/character`。
- 保存成功后刷新 editor 和 session。
- 提示“下一轮剧情将使用最新设定”。

### 8. 世界书抽屉

目标：收纳世界书编辑器。

包含：

- 标题
- 前提
- 基调
- 事实条目
- 保存按钮

验收标准：

- 打开抽屉时填充当前选择世界。
- 保存调用 `/api/editor/world`。
- 保存成功后刷新 editor 和 session。
- 事实条目仍可先用 textarea，后续再做条目化。

## 用户流程

### 开始新游戏

```text
点击顶部“新游戏”
打开新游戏面板
选择世界书
选择角色卡
点击“开始”
调用 POST /api/session/start
生成开场剧情
关闭面板并进入剧情舞台
```

验收标准：

- 新建后存档列表出现新存档。
- 左侧状态来自当前世界书。
- 剧情舞台显示 AI 开场。

### 继续存档

```text
点击顶部“存档”
打开存档抽屉
点击目标存档
调用 GET /api/session?id=session-id
刷新剧情、状态、角色和世界
关闭抽屉
```

验收标准：

- 当前存档高亮。
- 不会改变其他存档。
- 存档切换后行动选项正确刷新。

### 删除存档

```text
打开存档抽屉
点击存档右侧“删除”
弹出确认
确认后调用 POST /api/session/delete
刷新存档列表
如果删除的是当前存档，则切换到最新存档
```

验收标准：

- 删除前必须确认。
- 删除后该存档不再出现。
- 不遗留对应 messages。

### 编辑角色卡

```text
点击顶部“角色卡”
打开角色卡抽屉
修改字段
点击保存
调用 POST /api/editor/character
刷新 editor/session
显示保存成功提示
```

验收标准：

- 表单内容和当前角色一致。
- 保存后页面显示最新内容。
- 不破坏正在进行的消息列表。

### 编辑世界书

```text
点击顶部“世界书”
打开世界书抽屉
修改字段
点击保存
调用 POST /api/editor/world
刷新 editor/session
显示保存成功提示
```

验收标准：

- 表单内容和当前世界一致。
- 新开游戏会使用新世界书状态。
- 当前旧存档不强制重写 state。

### 发送行动

```text
点击行动选项或输入自由文本
调用 POST /api/message
禁用输入和按钮
显示 AI 推进中
返回后追加用户消息和 AI 消息
更新状态面板
恢复输入
```

验收标准：

- 请求期间不能重复提交。
- 返回失败时显示错误提示。
- fallback 回复也能正常渲染。
